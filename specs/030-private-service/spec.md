# День 30 — локальная LLM как приватный сервис: спецификация

Документ отвечает на вопросы «что» и «зачем». Как это строится, описано в
[plan.md](plan.md), по каким шагам — в [tasks.md](tasks.md). Код пишется только
после того, как владелец утвердит все три документа.

## 1. Задание (дословно)

> **День 30. Локальная LLM как приватный сервис**
> Разверните локальную LLM как сервис:
> 👉 на VPS или домашнем сервере
> 👉 с HTTP API
> 👉 с возможностью чата
>
> Проверьте:
> 👉 доступ к модели по сети
> 👉 стабильность при нескольких запросах
> 👉 базовые ограничения (rate limit / max context)
>
> Результат: Приватный AI-сервис на базе локальной LLM
> Формат: Видео + Код

## 2. Что говорит лекция недели 6

Лекция (`~/Загрузки/6-неделя-6-поток-v1-1.md`) называет главные доводы за
локальную модель — **приватность** и работу **без интернета**, а сервером может
быть и домашняя машина («один Mac Mini»). Она же предупреждает: локальная модель
не масштабируется как облако — ресурсы машины конечны, и это надо учитывать в
том, как сервис принимает запросы. Надёжность ответов даёт процесс и
**ограничение контекста**, а документы организации подмешиваются через RAG.

## 3. Толкование задания

| Слова задания | Что это значит в проекте |
|---|---|
| «домашний сервер» | Этот ноутбук в домашней сети (Wi-Fi, сейчас 192.168.1.43): сервис запускается службой пользователя systemd и переживает падение процесса. |
| «локальная LLM как сервис» | Отдельный процесс-шлюз перед Ollama. Ollama по-прежнему слушает только 127.0.0.1; наружу выходит только шлюз — со своими ключами, лимитами и журналом. Модель — `loc-rag-docs` (День 29). |
| «HTTP API» | OpenAI-совместимые `/v1/models` и `/v1/chat/completions` (с потоком), чтобы подключался любой клиент без доработок; плюс своя ручка «ответ по договорам» с источниками и дословными цитатами (Дни 24–29). |
| «с возможностью чата» | Страница чата сервиса: история разговора, ответ потоком, режим «по документам» для ключа с этим правом. |
| «приватный» | Доступ только по ключу API и только из разрешённых подсетей; HTTPS со своим сертификатом; сервис не делает внешних запросов (журнал сети Дня 27); в журнале запросов — только метаданные, без текстов вопросов и ответов. |
| «доступ по сети» | Запросы с другого сетевого хоста: клиент в контейнере Docker и телефон владельца в той же Wi-Fi; журнал сервиса показывает их адреса. |
| «стабильность при нескольких запросах» | Нагрузочный прогон ступенями 1 → 2 → 4 → 8 одновременных клиентов: ошибок сервера 0, задержка растёт предсказуемо (очередь), переполнение — понятный отказ, а не падение. |
| «rate limit / max context» | Лимит запросов на ключ, предел очереди, предел входа в токенах и предел ответа, предел размера тела, таймаут — каждый с понятным кодом и сообщением. |

| Развилка | Выбор |
|---|---|
| Где | **Ноутбук как домашний сервер** (домашняя сеть). |

| Стабильность | **Ступени 1 → 2 → 4 → 8 клиентов** на коротких вопросах чата + 2 одновременных вопроса по документам (≈ 1 ч машины). |
| Порядок | **SDD**, как в Днях 28–29. |

## 6. Требования

### 6.1 Функциональные

- **FR-01. Шлюз.** Отдельный процесс (`service.py`) принимает HTTPS-запросы и
  передаёт их в Ollama на 127.0.0.1:11434 (`/api/chat` — как агент: без
  «размышлений», с `keep_alive`, окном и пределом ответа). Служба Ollama не
  меняется. Шлюз не открывает ни интерфейс агента, ни инструменты MCP.
- **FR-02. Модели.** `GET /v1/models` — ровно одна модель, `loc-rag-docs`; запрос
  к другой модели — 404 в формате OpenAI (`model_not_found`).
- **FR-03. Чат по API.** `POST /v1/chat/completions` в формате OpenAI: `messages`,
  `temperature`, `max_tokens`, `stream`. Без потока — объект `chat.completion`
  с `usage` (токены входа и ответа — из `prompt_eval_count` и `eval_count`
  Ollama); с потоком — SSE `chat.completion.chunk` и `data: [DONE]`; причина
  остановки — `finish_reason` (`stop` или `length`). Текст ответа шлюз не
  меняет.
- **FR-04. Ответ по документам.** `POST /v1/documents/answer` (`{"question": …}`):
  ответ с источниками (`chunk_id`), дословными цитатами и их проверкой кодом —
  тот же путь, что `--rag-локально` Дня 29. Только для ключа с правом
  «документы»; поиск и документы — на этой машине.
- **FR-05. Ключи API.** Ключ — случайная строка, показывается один раз при
  создании; на диске — только хэш, имя, права (`чат`, `документы`, `админ`),
  время создания и отзыва. Без ключа — 401, без права — 403. Ключи создаются,
  перечисляются и отзываются из консоли.
- **FR-06. Подсети.** Запросы принимаются только из разрешённых подсетей
  (по умолчанию: 127.0.0.0/8, 192.168.1.0/24 — домашняя сеть, 172.17.0.0/16 —
  мост Docker по умолчанию, где работает клиент нагрузки; другие сети Docker,
  в том числе CRM, не входят); остальные — 403 до проверки ключа. Список — в
  настройках сервиса.
  Так сервис, оказавшись с ноутбуком в другой сети, не отвечает чужим.
- **FR-07. HTTPS.** Свой удостоверяющий центр и сертификат сервера на адреса
  127.0.0.1, текущий адрес в домашней сети, 172.17.0.1 и имена `localhost`,
  `host.docker.internal`; закрытые ключи — вне репозитория.
  Клиент в Docker проверяет сертификат по сертификату центра (без
  «отключить проверку»).
- **FR-08. Очередь.** Генерация — по одной за раз (на 2 ядрах параллельные
  генерации замедляют всех, День 29). Ожидающих — не больше N (по умолчанию 4);
  сверх — сразу 429 `queue_full` с `Retry-After` — оценкой ожидания по
  средней длительности. Положение в очереди и время ожидания видны клиенту
  (заголовки ответа и событие потока).
- **FR-09. Лимит запросов.** На ключ — не больше R запросов в минуту (по
  умолчанию 6; «ведро» с пополнением) ко всем ручкам `/v1/*`, включая
  `/v1/models`; сверх — 429 `rate_limited` с `Retry-After`. Лимит у каждого
  ключа свой.
- **FR-10. Предел контекста.** Вход (сообщения в шаблоне чата модели) считается
  в токенах до вызова модели; больше предела (по умолчанию 3400 = окно 4096 −
  ответ 600 − запас) — 413 `context_length_exceeded` с числом токенов и
  пределом. `max_tokens` больше 600 урезается до 600, и ответ об этом говорит
  (заголовок). Размер тела запроса — до 256 КБ, больше — 413.
- **FR-11. Таймаут и обрыв.** Генерация дольше T (по умолчанию 600 с) — 504; если
  клиент закрыл соединение, генерация в Ollama прерывается и место в очереди
  освобождается.
- **FR-12. Ошибки.** Все отказы — в формате OpenAI
  (`{"error": {"message", "type", "code"}}`) и по-русски в `message`.
- **FR-13. Журнал запросов.** На каждый запрос — строка JSONL: время, адрес
  клиента, имя ключа, ручка, код ответа, ожидание в очереди, длительность,
  токены входа и ответа. **Тексты вопросов и ответов не пишутся.**
- **FR-14. Приватность.** Сервис работает в офлайн-режиме Дня 27: облачные
  модели и внешние адреса заблокированы предохранителем; журнал сети сервиса
  показывает «внешних 0».
- **FR-15. Служба.** Сервис ставится службой пользователя systemd
  (`systemctl --user`), перезапускается при падении; есть `GET /health` без
  ключа (жив ли, модель, очередь — без чувствительных данных).
- **FR-16. Страница чата.** `/chat`: поле ключа (в памяти вкладки, не на
  сервере), история разговора, ответ потоком, режим «по документам», показ
  отказов (401/403/413/429) понятным текстом и ожидания в очереди.
- **FR-17. Страница сервиса.** `/admin` (ключ с правом «админ»): адрес и
  сертификат, лимиты, ключи (имена и права), очередь сейчас, последние запросы
  с адресами клиентов, память и CPU раннера, итоги нагрузочных прогонов.
- **FR-18. Нагрузочный прогон.** Клиент (`service_load.py`, asyncio + httpx)
  ступенями 1 → 2 → 4 → 8 одновременных клиентов, по 2 вопроса на клиента
  (16+ разных коротких вопросов общего вида, `max_tokens` 200); плюс 2
  одновременных вопроса по документам — только из проверенных без ПД
  (`local-opt.json → gpu.годные`, День 29). У каждого клиента свой ключ
  (`нагрузка-1…8`), чтобы мерить очередь, а не лимит ключа. Клиент повторяет
  запрос после 429 по `Retry-After` и пишет `finish_reason`. Запускается в
  контейнере Docker по сети; итоги — JSON и таблица на странице сервиса.
- **FR-19. Консоль.** `cli.py`: `--сервис установить|старт|стоп|статус`,
  `--сервис-ключ создать ИМЯ --права …`, `--сервис-ключи`, `--сервис-отозвать
  ИМЯ`, `--сервис-сертификат`, `--сервис-нагрузка`. Веб и консоль — одни и те
  же функции (память проекта: веб = консоль).

### 6.2 Метрики: определения

- **Задержка** — от отправки запроса до последнего байта ответа (клиент);
  **ожидание** — время в очереди шлюза до начала генерации (сервер);
  **первый токен** — до первого куска потока. По ступени — медиана (p50) и
  95-й перцентиль (p95).
- **Пропускная способность** — ответов в минуту на ступени.
- **Ошибки** — ответы 5xx, обрывы соединения и таймауты клиента. **Отказы** —
  429 (`queue_full`, `rate_limited`) и 413: это работа лимитов, не ошибки;
  считаются отдельно.
- **Ресурсы** — пик RSS и секунды процессора раннера (`resources.Наблюдатель`,
  День 29) и процесса шлюза за ступень; нагрузка машины.

### 6.3 Нефункциональные

- **NFR-01.** Шлюз держит соединения асинхронно: ожидающие в очереди не
  блокируют `/health` и страницу сервиса.
- **NFR-02.** Подсчёт токенов совпадает с `prompt_eval_count` Ollama на
  контрольных сообщениях (или расхождение известно и покрыто запасом — § 11, A-1).
- **NFR-03.** Тесты не ходят ни в Ollama, ни в сеть: подставные ответы и
  `httpx.MockTransport`/`TestClient`.
- **NFR-04.** Без ключей и сертификатов в репозитории; настройки по
  умолчанию — безопасные (доступ закрыт без ключа).

## 9. Конституция дня (постоянные ограничения)

1. **Документы организации** (`DocsSample/`), индекс, ключи API, сертификаты и
   их закрытые ключи в репозиторий не попадают. В отчётах, видео и коммитах
   нет фамилий, e-mail, отчеств и инициалов; список для проверки — локальный
   `pd-names.txt` (День 29). Журнал запросов — без текстов.
2. **Порты:** 5000 — сервер владельца, 5001 — стенд, 8766 — мок-трекер; сервис
   Дня 30 — **8443** (HTTPS). Гасятся только свои процессы, шаблон `pkill` — в
   скобках. Контейнеры CRM и параллельную сессию CRM не трогать.
3. **Служба Ollama не трогается**: ни переменные, ни перезапуск.
4. **Запись экрана** — только окно браузера.
5. **Ничего не пушить**: `git push` делает владелец.
6. **Имена файлов** — латиницей; тексты и ключи консоли — по-русски.
7. **`.py` не править**, пока работает стенд или идут прогоны; долгие прогоны —
   из снимка кода.
8. **Замеры — как есть**, с нагрузкой машины; сон ноутбука во время прогона
   проверяется по журналу системы, а крышку на это время не закрывают.
9. **Наружу — только домашняя сеть.** Сервис не публикуется в интернет (без
   проброса портов на роутере, без туннелей наружу).
10. **Черновики и логи** — в `Day-30/out/` (в `.gitignore`).

## 10. Вне рамок
