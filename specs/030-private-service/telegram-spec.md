# День 30, дополнение — Telegram-чат с локальной моделью: спецификация

Документ отвечает на вопросы «что» и «зачем». Как это строится — в
[telegram-plan.md](telegram-plan.md), по каким шагам — в
[telegram-tasks.md](telegram-tasks.md). Основная спецификация дня —
[spec.md](spec.md); здесь только то, что добавляет бот. Код пишется после
того, как владелец утвердит все три документа.

## 1. Запрос владельца (дословно)

> Давай добавим телеграм-чат для общения с локальной моделью в рамках задания дня 30.

## 2. Толкование

| Слова запроса | Что это значит в проекте |
|---|---|
| «телеграм-чат» | Бот Telegram: владелец пишет боту с телефона или компьютера, бот отвечает локальной моделью `loc-rag-docs`. Ответ появляется потоком — сообщение бота дописывается по мере генерации. |
| «с локальной моделью» | Бот не вызывает модель сам: он — ещё один клиент приватного сервиса Дня 30 (HTTPS, ключ API, лимиты, очередь). Модель, очередь и журнал сервиса — те же, что у `/chat` и клиентов по сети. |
| «в рамках задания дня 30» | Это ещё одна «возможность чата» и ещё один «доступ по сети»: бот работает на том же домашнем сервере, проходит те же лимиты и тот же предел контекста. |

**Что меняется в приватности.** Сервис по-прежнему не принимает входящих
соединений из интернета: бот сам опрашивает Telegram (long polling), проброса
портов и туннелей нет. Но всё, что владелец пишет боту и что бот отвечает,
проходит через серверы Telegram и хранится там. Поэтому: бот отвечает только
владельцу, а ответы по документам перед отправкой проходят фильтр
персональных данных.

## 3. Что уже есть и чего не хватает

| Есть (День 30 и раньше) | Не хватает |
|---|---|
| сервис: `/v1/chat/completions` с потоком, `/v1/documents/answer`, ключи с правами, лимиты, очередь, предел контекста (413), журнал без текстов | клиент сервиса, который говорит с Telegram |
| шаблоны ПД Дня 29 (`без_пд`: фамилии из локального `pd-names.txt`, отчества, инициалы, e-mail, телефоны) — только находят | **маскирование** найденного в тексте ответа, источниках и цитатах |
| офлайн-предохранитель Дня 27: всё внешнее блокируется, `OFFLINE_ALLOW` делает хост «локальным» | разрешить **один** внешний хост (`api.telegram.org`) и честно считать его внешним; токен бота в журнале сети — скрыт |
| служба systemd пользователя (`unit.py`), `/admin`, консоль `--сервис …` | вторая служба, карточка бота на `/admin`, консольные ключи бота |
| показ в браузере, запись окна, OCR кадров | показ Telegram Web без личных переписок в кадре |

Факты, проверенные до спецификации: `api.telegram.org` отвечает с ноутбука
(HTTP 302 за 0,8 с), но маршрут к нему идёт **через VPN** `amn0` — без VPN бот
не работает. Входящих соединений из интернета у ноутбука нет — webhook
невозможен, только long polling.

## 5. Требования

### 5.1 Функциональные

- **FR-T01. Бот — клиент сервиса.** Отдельный процесс `telegram_bot.py` ходит
  в сервис Дня 30 по HTTPS (127.0.0.1:8443, сертификат проверяется по
  `ca.crt`) со своим ключом API «телеграм» (права `чат`, `документы`). Модель
  напрямую не вызывает; лимиты, очередь и предел контекста — сервиса.
- **FR-T02. Получение сообщений — long polling.** `getUpdates` с ожиданием;
  updates обрабатываются последовательно по `update_id`. Следующий offset
  сохраняется после завершения обработки и успешной окончательной доставки
  ответа. Подтверждение Telegram — при последующем `getUpdates` с большим
  offset; неудачная окончательная доставка ответа владельцу и временные
  отказы не продвигают границу. Неподдерживаемые updates завершаются без
  ответа; для отказа чужому и выхода из группы per-update 400/403 терминальны
  (детали — D-T03 плана). Checkpoint содержит
  только номера и версию незавершённого перехода, без текстов. После аварии
  между доставкой и фиксацией возможен повторный ответ; восстановление
  ограничено сроком хранения updates Telegram. Входящих соединений нет.
- **FR-T03. Только владелец.** Отвечает только на личные сообщения от
  Telegram ID владельца (`.env`). Чужому — одно короткое «это частный бот» не
  чаще раза в сутки на человека; его текст в модель и в сервис не идёт;
  событие в журнале бота — «чужой» (без текста и без ID в открытом виде).
  Группы и каналы бот покидает.
- **FR-T04. Чат.** Обычное сообщение — вопрос модели через
  `/v1/chat/completions` с потоком. История — по чату, в памяти процесса
  бота (последние N реплик, не на диске); `/new` начинает разговор заново,
  `/new вопрос` — заново и сразу с этим вопросом (версия 5).
  413 `context_length_exceeded` — бот убирает самые старые реплики и
  повторяет сам; если не помещается и один вопрос — говорит об этом.
- **FR-T05. Ответ потоком.** Сначала — сообщение-заготовка (место в очереди
  сервиса, если ждём), затем бот правит его по мере генерации — не чаще
  раза в 1,5 с; в конце — подпись: модель, токены входа и ответа, ожидание в
  очереди, время. Пока ждём — «печатает…».
- **FR-T06. Документы.** `/doc вопрос` — `/v1/documents/answer`: ответ,
  источники (файл, раздел), цитаты с отметкой проверки; «не знаю» — как
  есть. Перед отправкой — фильтр ПД (FR-T07).
- **FR-T07. Фильтр ПД.** В тексте ответа, именах источников и цитатах
  маскируются совпадения шаблонов Дня 29: фамилии из `pd-names.txt`,
  отчества, инициалы с фамилией, e-mail, телефоны — каждое заменяется на
  «[скрыто]». Инициалы — в любом написании: «А.В.», «А. В.», «А.В» (без второй
  точки), «А В.»; поиск идёт по тексту, где латинские двойники кириллицы (A, B,
  C, E, H, K, M, O, P, T, X, Y и строчные a, c, e, o, p, x, y) заменены
  кириллицей — распознанные договоры смешивают письмо (версия 4). Под ответом — сколько фрагментов скрыто и каких видов (без
  самих значений). Цитата, в которой что-то скрыто, помечается «сокращена».
  Без `pd-names.txt` фильтр работает по общим шаблонам, а бот предупреждает,
  что фамилии не проверяются. **Чего фильтр не ловит:** адреса, ИНН, КПП,
  ОГРН, расчётные счета, паспортные данные, фамилии не из списка — это
  сказано в `/help` бота и в документах.
- **FR-T08. Отказы сервиса понятным текстом.** 429 — оба кода повторяемые,
  до общего срока (как у клиента нагрузки): `queue_full` — «очередь занята,
  повторю, как только освободится место (не позже чем через N с)»: бот
  смотрит `/health` раз в 5 с и повторяет, когда место есть, но не позже
  `Retry-After` (версия 3); `rate_limited` — «повторю через N с»; 413
  `question_too_long` у `/doc` — «вопрос длиннее 1000 знаков»; 401/403 —
  «ключ бота не принят / нет права»; сервис недоступен — «сервис не
  отвечает»; 5xx и обрыв — сообщение, а не тишина.
- **FR-T09. Команды.** `/start` и `/help` — что умеет бот и чего не ловит
  фильтр ПД; `/new`; `/doc …`; `/status` — служба, модель, очередь сервиса
  сейчас (через `/health`, вне лимита ключа).
- **FR-T10. Одно дело за раз.** Production polling завершает предыдущий update
  до начала следующего, включая успешную окончательную доставку ответа.
  `/status`, `/help`, `/start` владельца (в них нет вызова модели) отвечаются
  сразу, даже пока идёт генерация: бот раз в 2 с проверяет `getUpdates` с
  offset текущего update; checkpoint при этом не двигается дальше
  незавершённого update (версия 7, решение владельца).
- **FR-T11. Сеть бота.** Процесс бота работает с офлайн-предохранителем Дня
  27, в котором **разрешён один внешний хост — `api.telegram.org`**; он
  считается внешним и виден в журнале по имени. Любой другой внешний адрес
  блокируется. Токен бота в журнале сети, логах и журнале бота не
  появляется (в адресах Bot API он заменяется).
- **FR-T12. Журнал бота.** JSONL метаданных: время, кто (владелец / чужой),
  что (чат, документы, команда), код сервиса, токены, ожидание, длительность,
  сколько скрыто фильтром ПД, правок сообщения. Текстов вопросов и ответов
  нет.
- **FR-T13. Служба.** Служба systemd пользователя `day30-tg`
  (`Restart=on-failure`); сеть Telegram недоступна (VPN выключен) —
  повторы с нарастающей паузой, а не падение и не цикл перезапусков.
- **FR-T14. Консоль и страница.** Консоль: `--телеграм
  установить|старт|стоп|перезапуск|статус`, `--телеграм-ключ` (ключ бота для
  сервиса), `--телеграм-кто` (кто писал боту: ID и имя пользователя — чтобы
  записать ID владельца; текстов нет). `/admin`: карточка «Telegram-бот» —
  служба, имя бота, владелец задан или нет, последние события журнала бота,
  попытки чужих, сеть бота; кнопки старт и стоп (ключ «админ»).

### 5.2 Нефункциональные

- **NFR-T01. Секреты.** Токен бота и ID владельца — только в `.env` (в
  `.gitignore`); ключ сервиса для бота — файл 0600 в `memory/service/`.
  Профиль Chrome с сеансом Telegram Web владельца — 0700, вне репозитория.
- **NFR-T02. Зависимости.** Без новых библиотек: Bot API — через `httpx`
  (уже есть), чтобы и Telegram, и сервис подменялись в тестах
  `httpx.MockTransport`.
- **NFR-T03. Сервис не меняется по смыслу.** Модель, лимиты, журнал сервиса и
  его офлайн-режим (внешних 0) — те же; бот — внешний клиент.

## 9. Конституция дополнения

Действуют все пункты § 9 [spec.md](spec.md), с уточнениями:

1. **Пункт 9 («наружу — только домашняя сеть»)** — одно исключение: процесс
   бота делает исходящие запросы к `api.telegram.org`. Сервис по-прежнему не
   публикуется: ни входящих портов, ни туннелей, ни webhook.
2. **Документы в Telegram — только через фильтр ПД.** Тексты фрагментов
   документов (контекст модели) в Telegram не отправляются — только ответ,
   имена источников и цитаты, после маскирования.
3. **Токен бота** нигде не печатается: ни в журналах, ни в выводе консоли, ни в
   отчётах; проверка перед коммитом ищет его по значению из `.env` (при
   коммите, вне безопасного автоматического прогона `run_tests.py`, который
   настоящий `.env` не читает — версия 7).
4. **Telegram Web владельца** ведёт только скрипт показа и только в чате с
   ботом; профиль с сеансом удаляется после записи видео по слову владельца.
5. **Сообщения владельцу** бот отправляет только в ответ на его сообщения и
   один раз в живой проверке (`check_telegram.py --живой`, с предупреждением).

## 10. Вне рамок

- несколько пользователей, привязка по коду, группы, каналы, inline-режим;
- голос, файлы, картинки; документы, присланные в Telegram;
- webhook, публичный адрес, хостинг бота вне ноутбука;
- хранение истории чата на диске (только в памяти процесса бота);
- работа без VPN (маршрут к Telegram — через `amn0`).
