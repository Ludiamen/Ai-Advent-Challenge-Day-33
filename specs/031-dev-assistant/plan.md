# День 31 — ассистент разработчика: план

Как строится то, что описано в [spec.md](spec.md). Задачи — [tasks.md](tasks.md).

## 1. Архитектура

```
 консоль: cli.py --чат / --реплика "/help …"      веб: /chat  «/help …»
                 │                                         │
                 └──────────────┬──────────────────────────┘
                                ▼
            agent/devassist/assistant.py — Ассистент(проект, модель)
              1. контекст: git_branch + git_status (MCP, всегда)
              2. поиск: индекс проекта index-projects/crm/ (реранкер)
              3. модель (роль «ассистент разработчика») + инструменты
                 git_ls_files / git_diff / git_log (круги ≤ 3)
              4. ответ JSON с цитатами → проверка цитат кодом → «не знаю»
              5. запасной путь: облако ✗ → локальная; git ✗ → только документы
              6. маска ПД на выходе; строка метрик в журнал (без текстов)
                 │                         │
                 ▼                         ▼
     agent/devassist/project.py      git_server.py (stdio MCP, только чтение)
     projects.json → проект,           git -C <CRM> branch/status/ls-files/
     индекс, «включить/исключить»,       diff/log, GIT_OPTIONAL_LOCKS=0,
     маска ПД до индекса                 корень проекта, пределы размера

 Telegram: «/help вопрос» ─► telegram.py (очередь чата, правки хода, 429)
                              └─► HTTPS 127.0.0.1:8443 POST /v1/project/help
                                   (ключ с правом «проект»)
                                   service.py → тот же Ассистент
                                   модель — service.json «проект.модель»
                                   офлайн-предохранитель: наружу только api.deepseek.com
                              ◄── JSON ─► маска ПД ─► ответ правками
```

Ассистент — один модуль на все каналы: консоль и веб зовут его в процессе
агента, сервис — в своём процессе. Бот не знает об устройстве ассистента, он
клиент ручки сервиса (как с `/doc`).

## 2. Решения

- **D-01. Проекты — `projects.json`.** `{"по_умолчанию": "crm", "проекты":
  {"crm": {"путь": "~/Документы/CRM", "описание": "…", "включить": [...],
  "исключить": [...], "индекс": "index-projects/crm"}}}`. Шаблоны — `fnmatch`
  по путям из `git ls-files` (только файлы под git: в индекс не попадёт
  неотслеживаемое и игнорируемое). Для CRM «включить»: `README.md`,
  `CLAUDE.md`, `docs/*.md`, `docs/**/*.md`, `specs/**/*.md`,
  `backend/**/models.py`, `backend/**/urls.py`; «исключить»: `docs/reviews/**`,
  `HANDOFF.md`. Путь можно переопределить окружением `PROJECT_<ИМЯ>_DIR`.
- **D-02. Индекс проекта — тот же `Индексатор`.** Файлы проекта
  копируются в промежуточный каталог `index-projects/crm/src/` (после маски
  ПД точного профиля, D-02a, с сохранением относительных путей), и `Индексатор(документы=src,
  индекс=index-projects/crm)` строит индекс как обычно. Так индексатор не
  меняется, маска ПД гарантированно применена до разбиения (FR-03), а
  `source` фрагмента — относительный путь в CRM. Повторная индексация
  сравнивает sha256 содержимого с прошлым списком (`manifest.json`).
  `.json` не индексируется (`constitution.md` — собранный из JSON текст).
- **D-02a. Точный профиль маски.** `pd.скрыть(текст, профиль="полный")` —
  прежнее поведение по умолчанию (бот `/doc`, договоры, тесты Дня 30 без
  правок ожиданий); `профиль="точный"` — фамилии из списка целым словом без
  учёта регистра, e-mail, телефоны (`+7`/`8` и группы с разделителями, не
  соседствуют с буквами и шестнадцатеричными цифрами), «А.В. Фамилия» и
  «Фамилия А.В.» только кириллицей; без латинских двойников. Неоднозначное ФИО
  в точном профиле не поднимает ошибку, а маскируется. Индекс пробы ворот 0
  строился полным профилем — после введения точного профиля переиндексация
  (векторы из кэша, кроме изменённых фрагментов).
- **D-03. git-сервер.** `git_server.py` по образцу `mcp_server.py`
  (`MCPServer`, `ToolAnnotations(read_only_hint=True, destructive_hint=False,
  open_world_hint=False)`, `ToolError`). Каждый вызов — `subprocess.run(["git",
  "-C", корень, …], env={…, "GIT_OPTIONAL_LOCKS": "0", "GIT_TERMINAL_PROMPT":
  "0"}, timeout=20)`; аргументы — только из белого списка (ссылки проверяются
  `git rev-parse --verify`, пути — внутри корня, без `..` и абсолютных);
  `git_diff` — предел 20 000 символов с пометкой «обрезано»; `git_ls_files`
  — шаблон и предел 300 строк; `git_log` — до 30 коммитов, формат «хэш · дата
  · тема». Корень — аргумент запуска `--корень` (в `mcp-servers.json`
  `${PROJECT_CRM_DIR:-~/Документы/CRM}`). В `mcp-servers.json`: `"только_чтение":
  true`, темы «git, ветка, diff, файлы проекта».
- **D-04. Ассистент — `agent/devassist/assistant.py`.** Класс `Ассистент(проект,
  клиент, ящик_mcp, модель)`, метод `спросить(вопрос) -> ОтветАссистента`:
  1. `git_branch`, `git_status` через `Toolbox` (короткий таймаут); ошибка → пометка;
  2. `Поисковик` по индексу проекта. **Облачной модели** (версия 2, по замеру) — 10
     фрагментов по косинусу без второго этапа: кросс-энкодер 16→6 на этом ноутбуке
     шёл 60–80 с, а отбор почти тот же (лишнее отсеивает модель); LLM-реранкер в
     сервисе не пропустил бы предохранитель. Плюс **файлы схем**: вопрос о маршрутах
     или полях и названное приложение (синонимы — `projects.json` → «схемы») добавляют
     лучшие куски нужного `urls.py` / `models.py` — косинус русского вопроса их часто не
     поднимал. Для локальной модели (выбор в чате,
     запасной путь, режим сервиса «локально») — **локальный профиль** Дней
     27–30 (`profile.локальный`: меньше фрагментов, кросс-энкодер), иначе
     вход не помещается в окно 4096 `loc-rag-docs`;
  3. сообщения: роль (D-05) + фрагменты с номерами + блок «состояние git» +
     вопрос; `tools` — `git_ls_files`, `git_diff`, `git_log` (имена
     `git__…`); до 3 кругов вызовов, затем ответ без инструментов;
  4. ответ — JSON формата Дня 24 (`ответ`, `источники`, `цитаты`, `не_знаю`,
     `уточнение`); цитаты проверяет `cite.py`; ответы из git (без цитат из
     документов) допустимы, если был вызов инструмента и вопрос о git;
  5. запасной путь (D-07), маска ПД (`pd.скрыть`) на выходе, метрики (D-09).
  Цикл инструментов — свой, короткий, по образцу `MemoryAgent._ответ_модели`;
  `MemoryAgent` не трогается.
- **D-05. Роль.** `agent/devassist/prompts.py`: «Ты — ассистент разработчика
  проекта «{описание}». Отвечай по фрагментам документации и коду проекта и по
  состоянию git; называй файлы и разделы; если ответа нет — «не знаю» и
  уточнение; инструменты только читают git». Версия 2: ассистент собирает
  сообщения сам (роль, фрагменты, блок git, вопрос), а из `cite.py` берёт только
  разбор JSON и проверку цитат — `cite.py` и `answer.py` не меняются, прежние пути
  Дней 22–30 не задеты.
- **D-06. `/help` — общий разбор команды.** `agent/devassist/command.py`:
  `разобрать(текст) -> ("справка" | "вопрос", вопрос)`. Консоль: в `чат_cli` —
  до `чат.ход` на обоих путях (`--реплика` и диалог); веб: в `api_chat_say` —
  до ветки потока; ответ — в формате хода чата (`text`, `sources`, `stages`) плюс
  поля `git`, `tools`, `fallback`; поток — события «готово» / «ошибка». Ход
  записывается в историю чата с пометкой «/help». Справка чата
  (`КОМАНДЫ_ЧАТА`) дополняется `/help`.
- **D-07a. Надёжность ответа (версия 2, найдено показом).** Предел ответа облака
  2000 токенов (на 1200 JSON обрывался); ответ не в формате JSON после повтора —
  «не знаю» с пометкой, а не сырой текст; «посмотрю в git» без вызова — одно
  напоминание; для ответов по выводу git проверка «числа ответа — из цитат» снята
  (подсчёт по прочитанному файлу); локальной модели — вывод инструмента до 3000
  символов и 2 круга (на CPU файл из `git_show` читался минутами).
- **D-07. Запасной путь.** Облачный вызов: таймаут 60 с, один повтор через 3
  с; затем — локальная модель роли «ответ-по-документам» (в сервисе —
  `loc-rag-docs`) с пометкой в ответе; если и она не ответила — понятная ошибка
  с советом. git: таймаут 20 с, ошибка — ответ по документам, пометка «git
  недоступен: …». Неразборчивый JSON — один повторный запрос (как в Дне 24),
  затем «не знаю».
- **D-08a. MCP в процессе сервиса** (отступление от SPEC-030, FR-01, принято
  владельцем вместе с выбором «ручка сервиса»): `Toolbox` с одним сервером
  `git` открывается лениво при первом запросе к ручке проекта и закрывается
  при остановке сервиса; если не работает (A-7) — ассистент в сервисе зовёт
  функции `git_server` напрямую, как библиотеку.
- **D-08. Ручка сервиса.** `gateway.py`: `POST /v1/project/help` — копия пути
  `/v1/documents/answer` (ключ → лимит → тело → вопрос → очередь → поток →
  обрыв → таймаут) с правом «проект» (`keys.ПРАВА` += «проект»); отвечатель —
  колбэк `помощник` в `Сервис(...)`. `service.json`: `"проект": {"имя": "crm",
  "модель": "ds-flash", "запасная": "loc-rag-docs"}`. Офлайн в `service.py`:
  `OFFLINE_ALLOW_EXTERNAL=api.deepseek.com` выставляется при запуске
  **всегда**, а `offline.проверить_модель` пропускает облачную модель, если её
  хост в `OFFLINE_ALLOW_EXTERNAL` (ворота 0, A-4; в агенте без этой переменной —
  прежний отказ) — так переключатель работает без перезапуска; облачную модель в
  процессе сервиса может вызвать только ассистент ручки проекта при
  переключателе «облако» (проверка в коде, тест: чат и документы зовут только
  `loc-rag-docs`; журнал сети: в режиме «локально» внешних 0). Переключатель:
  `cli.py --сервис-проект-модель облако|локально` (пишет `service.json` и
  сообщает работающему сервису через ручку админа — без перезапуска) и кнопка на
  `/admin` (`POST /admin/api/project-model`, ключ «админ»). Журнал: новое
  поле «модель» в белом списке, тексты — по-прежнему нет.
- **D-09. Метрики.** `agent/devassist/metrics.py`: строка JSONL на ответ в
  `memory/devassist/metrics.jsonl` (консоль, веб) и
  `memory/service/devassist.jsonl` (сервис): время, канал, проект, модель,
  запасной, инструменты (имена), не_знаю, вход/ответ токенов, этапы (git,
  поиск, модель, всего), код. `--помощь-метрики` сводит p50/p95 и доли.
- **D-10. Бот.** `telegram.py`: `/help` без остатка — `ПОМОЩЬ` (мгновенно,
  + строка «/help вопрос — вопрос о проекте CRM»); с остатком — **не** в
  `СРАЗУ` и не в `_мгновенная`: обычная очередь чата, `_проект(вопрос)` по
  образцу `_документы` (правки хода «ищу в документах проекта… N с»,
  `_с_повторами` при 429, `собрать_документы`-подобная сборка под маской ПД).
  `КлиентСервиса.проект(вопрос)` → `/v1/project/help`. Журнал бота: вид
  «проект». Ключ бота — с правами «чат», «документы», «проект».
- **D-11. Службы `day31-*`.** `unit.py`: `ИМЯ = "day31-llm.service"`,
  `ИМЯ_БОТА = "day31-tg.service"`, `After=` — из констант (не строкой);
  описания «День 31». Перенос: `memory/service/` Дня 30 (ключи, tls, журналы,
  `telegram.key`, состояние бота, offset) копируется в `Day-31/memory/service/`
  **при остановленных** `day30-*`; затем `day30-*` — `stop` и `disable`,
  `day31-*` — `установить` и `старт`. Префикс ключей `sk-day30-` не меняется
  (иначе прежние ключи владельца не подойдут). Порт 8443 тот же.
- **D-12. Тесты.** Новый модуль `test_devassist.py` в `run_tests.py`
  (`МОДУЛИ`); первый коммит Дня 31 — перенос Дня 30 без изменений, чтобы
  `run_tests.py` видел файлы. Временный репозиторий git в тестах — свой
  (`git init` во временном каталоге), CRM в тестах не участвует.
- **D-13. Контрольный набор `dev-questions.json`.** 10 вопросов о структуре
  CRM: эталонные факты (ключевые слова, которые обязан содержать ответ) и
  ожидаемые источники (файлы); 2 ловушки; 3 вопроса о git (ветка, последние

## 4. Доказательный прогон `check_devassist.py`

1. **Индекс** — файлы индекса = файлы по «включить / исключить» из `git
   ls-files` CRM; ни одного из `docs/reviews/`; скан всех фрагментов на ПД — 0;
   число фрагментов и время.
2. **git-сервер** — настоящий процесс `git_server.py` через клиент MCP:
   ветка = `git branch --show-current`, `git_log` = `git log`, `git_diff` с
   пределом; путь вне корня, неизвестная ссылка, неизвестный инструмент —
   понятные отказы; нет инструментов, меняющих репозиторий (список
   инструментов сверяется с белым списком); `.git/index` CRM — mtime до и после.
3. **Контрольный набор** — ds-flash и локальная модель: таблица по вопросам
   (верно, источник, цитаты, инструменты, время, токены); критерии SC-04.
4. **Запасной путь** — облако «недоступно» (подменный адрес DeepSeek) →
   локальная с пометкой; git «недоступен» (несуществующий корень) → документы
   с пометкой; меняющая просьба → «такого инструмента нет».
5. **Ручка сервиса** — стенд сервиса на 8444 со своей памятью: 401/403, ответ,
   429 по лимиту, журнал без текстов; режим «локально» — внешних 0; «облако» —
   внешний только `api.deepseek.com`.
6. **Метрики** — `--помощь-метрики` по журналу прогона: p50/p95, доли.
7. **Наши процессы не пишут в CRM** — короткое окно (spec, NFR-01): полный
   набор инструментов git-сервера и проба индексации; mtime `.git/index`,
   `HEAD`, `git status --porcelain` сразу до и сразу после; `HEAD` сдвинулся —
   окно повторяется, причина в отчёте.

- `БотHelp` — `/help` без текста мгновенно; `/help вопрос` — в очереди, не
