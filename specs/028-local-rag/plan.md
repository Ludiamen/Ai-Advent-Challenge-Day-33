# День 28 — локальная LLM + RAG: план реализации

Как выполнить [spec.md](spec.md). Ссылки FR-, SC-, NFR- и A- ведут туда, а
порядок работ разложен в [tasks.md](tasks.md).

## 1. Архитектура

```
вопрос
  │
  ├─ ПрофильRAG ──────────────── agent/rag/profile.py (новый) ← local-roles.json
  │    поиск: реранкер «кросс», K 8 → 2, порог косинуса; порог «не знаю» 0,015;
  │    лучшее окно; схема ответа «цитаты»; модель ответа
  │
  ├─ поиск (локально, без LLM) ── agent/rag/retrieval.py, rerank.py, store.py
  │    вектор bge-m3 (Ollama) → косинус (SQLite) → кросс-энкодер (ONNX) → окна
  │    этапы: progress.этап("поиск", вектор=…, косинус=…, кросс=…, кандидатов=…, в_промпт=…)
  │    без_кэша=True — не читать кэш векторов и оценок (повтор 1, «новый вопрос»)
  │
  └─ ответ ────────────────────── agent/rag/answer.py
       Отвечатель.ответить(вопрос, модель=loc-…, отбор=<готовый поиск>, профиль=…)
       этап «ответ · loc-… (локально)», токены потоком; замеры Ollama в ОтветRAG

сравнение ─────────────────────── agent/rag/localbench.py (новый)
  для повтора 1..3, для вопроса 1..14:
     поиск один раз (локальный профиль; повтор 1 — без кэша) ─┬─ лок-4b        (loc-qwen35)
                                                              ├─ лок-1.7b      (loc-qwen17)
                                                              └─ облако-тот-же (ds-flash)
     свой поиск «фильтр» Дня 24 ────────────────────────────── облако-лучшее (ds-flash)
  каждый ответ: citecheck.проверить → судья → дельта журнала сети → строка JSONL
  сводка: качество / скорость / стабильность (spec § 6.2) → LOCAL-RAG.md, index/local-rag.json

интерфейсы
  консоль  cli.py: --rag-локально, --rag-рядом, --сравнить-локально, --отметить-rag

проверки   tests.py, check_local_rag.py, check_cli.py (часть 28), browser.mjs (режимы и показ)
```

## 2. Решения

**D-01. Профиль вместо глобального флага (FR-01).** Сейчас три места
ветвятся по `offline.включён()`:
- `answer._порог_уверенности`;
- `answer._лучшие_окна`;
- `retrieval.Поисковик.настройки`.

Теперь они читают `ПрофильRAG`: явный, переданный в `ответить(профиль=…)`, или
текущий. Текущий профиль в офлайне — `локальный`, иначе — как в Дне 24. Это
единственная правка, которая задевает код Дня 27. Поведение без профиля и вне
офлайна не меняется, это закрепляют тесты Дней 23–27.

**D-02. Один поиск на три участника (FR-05).**
- Для `лок-4b`, `лок-1.7b` и `облако-тот-же` поиск выполняется один раз на
  вопрос и повтор, его результат (`отбор`) передаётся всем троим. Совпадение
  фрагментов закрепляет тест: одинаковые `chunk_id` и одинаковые окна.
- У `облако-лучшее` поиск свой — «фильтр» Дня 24, его LLM-реранкер облачный.
- Порог «не знаю» у первых трёх общий, из локального профиля. Поэтому их «не
  знаю по порогу» совпадает, и разница между ними — только генерация.

**D-03. Порядок прогона — по вопросам, участники вперемешку.**
- Все четыре участника получают вопрос при одной и той же нагрузке машины.
- Если A-2 не подтвердится (модели вытесняют друг друга из памяти), порядок
  меняется на блоки по модели, а время загрузки идёт в отчёт отдельно.

**D-04. «Новый вопрос» и «повтор» (FR-07).**
- **Повтор 1:** кэш оценок кросс-энкодера не читается (`без_кэша`), но
  пишется. Вектор вопроса и лучшие окна не кэшируются вовсе (A-3). Промпт
  модель видит впервые.
- **Повторы 2–3:** кэши живые.
- **Попадание в кэш промпта Ollama** (A-1 — по счётчику не видно): промпт
  считается взятым из кэша, если скорость чтения `prompt_eval_count /
  prompt_eval_duration` ≥ 100 токенов в секунду. Без кэша на этой машине 4B
  читает 7–16, 1.7B — 25–40; из кэша — 420 и 3300 (проба ворот 0). Флаг и
  скорость пишутся в каждый ответ.

**D-05. Журнал прогона и продолжение (FR-06, NFR-03).**
- Каждый ответ — строка в `index/local-rag/run-<метка>.jsonl`, ключ —
  `(вопрос, участник, повтор)`. Состояние лежит в `index/local-rag/state.json`.
- Повторный запуск с той же меткой пропускает готовые тройки.
- Сводка и отчёт собираются из журнала в любой момент; незавершённый прогон
  помечен «не завершён: N из 168».
- `index/` в `.gitignore`. В репозиторий идёт `LOCAL-RAG.md`, его пишет код.

**D-06. Судья — `ds-pro` (spec § 5, решение владельца).**
- Один судья на всех четырёх участников. Вердикт хранится в ответе.
- Ключ `--пересудить` заново спрашивает судью по журналу без новых ответов:
  если судью поменяют, ответы не пересчитываются.

**D-07. Ход ответа на `/rag` (FR-03).**
- `/api/rag/cited` с `stream: true` отдаёт NDJSON, как `/api/chat/say` в Дне 27:
  события «этап», «токены», итог.
- `/api/rag/side` — четыре участника на одном вопросе: события с меткой
  участника, итог по каждому.

**D-08. Сравнение в фоне из веба (FR-11).**
- Поток-демон запускается так же, как сборка индекса Дня 21: замок, одна
  работа за раз.
- Ход пишется в тот же `state.json`, что и у консоли, поэтому прогон, начатый
  в консоли, виден на странице, и наоборот.
- Повторный старт продолжает прогон, а не начинает заново.

**D-09. Отметки (FR-10).** `bench.отметить(память, задача="rag:<id вопроса>",
модель=<участник>, оценка, заметка)` — тот же `marks.jsonl` Дня 26. В отчёте
отметки идут колонкой: последняя отметка на пару.

**D-10. Чистка веба (FR-13, spec § 9).**
- Из шаблонов удаляются разметка и скрипт убранных панелей, из `web.py` —
  их маршруты, из `tests.py` — их веб-тесты, из `browser.mjs` — их режимы.
- Серверные модули (`agent/scheduler`, `agent/pipeline`, `agent/orchestra`,
  профиль, сценарии, инварианты) и ключи консоли остаются, вместе с их тестами
  и шагами `check_cli`.
- В `MANUAL-CHECK.md` части 11–20 — пометка «в вебе убрано в Дне 28, проверка
  — в CLI-CHECK.md».

**D-11. Описание недели.** На каждой странице вместо подневных блоков — один
абзац: «Неделя 6 — локальная модель: установка и сравнение (День 26), всё
приложение офлайн (День 27), локальный RAG и сравнение с облаком (День 28)».
Плюс ссылки на страницы.

## 5. Проверки до прогонов (тесты пишутся раньше кода модуля)

- **`ПрофильRAG`:** берётся из карты; явный профиль сильнее флага офлайна; без
  профиля и вне офлайна — поведение Дня 24; облачный профиль Дня 24.
- **`ПоискБезКэша`:** `без_кэша` не читает кэш векторов и оценок, но пишет его;
  разбивка секунд есть; этап «поиск» уходит наблюдателю.
- **`ОдинПоискТриУчастника`:** одинаковые `chunk_id`, окна и решение порога у
  `лок-4b`, `лок-1.7b` и `облако-тот-же`.
- **`ПрогонСравнения`:**
  - строка JSONL на ответ;
  - продолжение пропускает готовые тройки;
  - незавершённый прогон даёт частичную сводку;
  - дельта сети на ответ.
- **`МетрикиКачестваСкоростиСтабильности`:** формулы spec § 6.2 на
  синтетических записях — стабилен или нет, дословная устойчивость, починки,
  ошибки, медиана, коэффициент вариации, колонки «новый» и «повтор».
- **`ОтчётLocalRag`:** таблицы, условия прогона, ответы целиком; в отчёте нет
  `DocsSample` и абсолютных путей.
- **`ОтметкиRAG`:** запись, последняя на пару, колонка в отчёте.
- **`ВебЛокальногоRAG`:**
  - поток `/api/rag/cited`;
  - `/api/rag/side`;
  - старт, продолжение и ход `/api/rag/localbench`;
  - `/api/rag/mark`;
  - убранных маршрутов нет (404).
- **`КонсольДня28`:** ключи, коды возврата, пустой вопрос — ошибка без вызова
  модели.
- **`СтраницаЦела`:** нет «День N» при N ≤ 20, нет удалённых id; остальное на
  месте.

Тесты не ходят ни в Ollama, ни в облако: подменяются `httpx.MockTransport` и
подставные клиенты, как в Днях 26–27.
