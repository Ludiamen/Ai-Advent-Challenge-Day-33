# Приватный AI-сервис: как подключиться

Сервис — шлюз `service.py` перед локальной Ollama на ноутбуке в домашней сети.
Модель — `loc-rag-docs` (`qwen3.5:4b`, оптимизированная в Дне 29). Запросы
чата и документов не уходят с машины: Ollama слушает только 127.0.0.1, шлюз
работает в офлайн-режиме. Исключение одно (День 31): ассистент проекта
(`/v1/project/help`) в режиме «облако» ходит в `api.deepseek.com` — это
единственный внешний хост процесса сервиса; в режиме «локально» внешних 0.

## Адрес и сертификат

- Адрес: `https://<адрес ноутбука в домашней сети>:8443` — его печатает `python
  cli.py --сервис-сертификат` (строка «Адреса и имена»).
- Сертификат выпущен своим центром. Клиенту нужен файл центра
  `memory/service/tls/ca.crt` (открытый, его можно раздавать). Закрытые ключи
  центра и сервера остаются на ноутбуке.
- Сменился адрес ноутбука (DHCP, другая сеть) — `python cli.py
  --сервис-сертификат` и `python cli.py --сервис перезапуск`: центр прежний,
  `ca.crt` клиентам менять не нужно.

## Ключи

```bash
python cli.py --сервис-ключ ИМЯ --права чат                  # чат
python cli.py --сервис-ключ ИМЯ --права чат,документы        # и ответ по документам
python cli.py --сервис-ключ ИМЯ --права админ                # страница /admin
python cli.py --сервис-ключ ИМЯ --права проект               # ассистент разработчика /v1/project/help (День 31)
python cli.py --сервис-ключи                                 # имена и права (самих ключей нет)
python cli.py --сервис-отозвать ИМЯ
```

Ключ показывается один раз; на диске хранится только его хэш. Передаётся
заголовком `Authorization: Bearer sk-day30-…`.

## Примеры

```bash
A=https://192.168.1.43:8443; K=sk-day30-…
curl --cacert ca.crt $A/health
curl --cacert ca.crt -H "Authorization: Bearer $K" $A/v1/models
curl --cacert ca.crt -H "Authorization: Bearer $K" -H 'Content-Type: application/json' \
     -d '{"messages":[{"role":"user","content":"Что такое SLA?"}],"max_tokens":200}' $A/v1/chat/completions
curl -N --cacert ca.crt -H "Authorization: Bearer $K" -H 'Content-Type: application/json' \
     -d '{"stream":true,"messages":[{"role":"user","content":"Что такое SLA?"}]}' $A/v1/chat/completions
curl --cacert ca.crt -H "Authorization: Bearer $K" -H 'Content-Type: application/json' \
     -d '{"question":"До какого числа нужно оплачивать услуги связи по договору VPN с Ростелекомом?"}' \
     $A/v1/documents/answer
curl --cacert ca.crt -H "Authorization: Bearer $K" -H 'Content-Type: application/json' \
     -d '{"question":"Какие модели данных есть в приложении org?"}' $A/v1/project/help
```

**Ассистент разработчика (День 31)** — `POST /v1/project/help` (`{"question": …}`, ключ с
правом «проект»): ответ о проекте CRM по его документации и git (только чтение) — JSON с
полями `answer`, `sources` (файл, раздел, `chunk_id`), `quotes` (с проверкой), `git`
(ветка, коммит, статус), `tool_calls` (вызовы git с аргументами), `notes` (запасной путь,
недоступный git), `usage`, `timings`. Лимит ключа, предел тела и вопроса, очередь, обрыв,
таймаут и журнал без текстов — как у ответа по документам; в журнале — модель ответа.
Модель — переключатель без перезапуска: `python cli.py --сервис-проект-модель
облако|локально` или кнопки на `/admin` («Ассистент проекта»).

```python
import httpx
from openai import OpenAI

клиент = OpenAI(base_url="https://192.168.1.43:8443/v1", api_key="sk-day30-…",
                http_client=httpx.Client(verify="ca.crt", timeout=600))
print(клиент.chat.completions.create(model="loc-rag-docs",
      messages=[{"role": "user", "content": "Что такое SLA?"}]).choices[0].message.content)
```

## Страницы

- `/chat` — чат и ответ по документам. Ключ вводится в поле (хранится только во
  вкладке) или приходит в ссылке `…/chat#key=sk-day30-…`: часть после `#` на
  сервер не уходит, страница кладёт ключ в память вкладки и стирает его из
  адресной строки. Так удобно открывать с телефона.
- `/admin` — состояние (ключ с правом «админ»): служба, сертификат, лимиты,
  очередь в реальном времени, память раннера, журнал сети, ключи, клиенты по
  адресам, журнал запросов, нагрузка.

## Лимиты и отказы

| Что | Предел | Отказ |
|---|---|---|
| подсеть клиента | 127.0.0.0/8, 192.168.1.0/24, 172.17.0.0/16 (`service.json`) | 403 `forbidden_network` — до проверки ключа |
| ключ | есть, не отозван | 401 `missing_api_key` / `invalid_api_key` |
| права | чат / документы / админ | 403 `permission_denied` |
| запросов на ключ | 6 в минуту ко всем `/v1/*` | 429 `rate_limited`, `Retry-After` |
| очередь | 1 генерация + 4 ждут | 429 `queue_full`, `Retry-After` |
| вход | ≤ 3400 токенов (окно 4096 − ответ 600 − запас) | 413 `context_length_exceeded` — до модели |
| ответ | `max_tokens` ≤ 600 | больше — урезается, заголовок `X-Max-Tokens-Clamped` |
| тело запроса | ≤ 256 КБ | 413 `request_too_large` |
| вопрос по документам | ≤ 1000 символов | 413 `question_too_long` |
| генерация | ≤ 600 с | 504 `timeout` |

`Retry-After` — оценка сервиса: медиана последних 20 генераций × очередь.
После коротких запросов она занижена, поэтому повторяйте до общего срока
(клиент нагрузки ждёт до 20 минут), а не ограничивайте число попыток.

Все отказы — в формате OpenAI: `{"error": {"message", "type", "code"}}`, текст
по-русски. Положение в очереди видно в заголовках `X-Queue-Position` и
`X-Queue-Wait`, а в потоке — в комментарии `: очередь N`. Если закрыть
соединение посреди потока, генерация прерывается и место в очереди
освобождается.

## Память

Модель занимает около 2,9 ГБ. Кроме неё `llama-server` в Ollama копит кэш
промптов недавних запросов вместе с контрольными точками состояния, по 100–200
МБ на запрос. Предел кэша — 8 ГБ по умолчанию: под долгой нагрузкой раннер
займёт до ≈ 11 ГБ, а через 30 минут простоя выгрузится. Предел задаёт
переменная `llama-server` `LLAMA_ARG_CACHE_RAM` (в МиБ; так пишет его справка).
Доходит ли она до раннера, если задать её процессу Ollama, этот день не
проверял: службу Ollama он не трогал.

## Telegram-бот

Бот — ещё один клиент сервиса: процесс `telegram_bot.py` (служба `day30-tg`)
ходит в `https://127.0.0.1:8443` со своим ключом «телеграм» (чат, документы) и
сам опрашивает Telegram (long polling) — входящих соединений к ноутбуку нет.
Отвечает **только владельцу** (один Telegram ID); чужому — «Это частный бот.» не
чаще раза в сутки, его текст в модель не идёт; из групп бот выходит. Маршрут к
`api.telegram.org` у владельца идёт через VPN — без VPN бот ждёт и
переподключается сам.

Один раз:

1. @BotFather: `/newbot`, затем `/setjoingroups` → бот → **Disable**.
2. `Day-30/.env`: `TELEGRAM_BOT_TOKEN=<токен>` (в переписку и в git не
   попадает).
3. Напишите боту `/start`, затем при остановленном боте `python cli.py
   --телеграм-кто` — свой ID запишите в `.env`: `TELEGRAM_OWNER_ID=<ID>`.
4. `python cli.py --телеграм-ключ` — ключ сервиса для бота в
   `memory/service/telegram.key` (0600).
5. `python cli.py --телеграм установить`, `python cli.py --телеграм старт`.

Дальше: `python cli.py --телеграм статус` или карточка «Telegram-бот» на `/admin`
(там же «Запустить» и «Остановить»).

| В Telegram | Что делает бот |
|---|---|
| вопрос | `/v1/chat/completions` с потоком: сообщение «⏳ …» дописывается правками не чаще раза в 1,5 с, внизу — модель, токены, очередь, время; итог — с разметкой (жирный, код, заголовки, списки) |
| уточнение | история чата — последние 6 пар реплик, в памяти процесса бота (не на диске); 413 по контексту — бот сам убирает старые реплики |
| очередь занята (429) | `queue_full` — бот раз в 5 с смотрит `/health` и повторяет, как только освободилось место, но не позже `Retry-After`; `rate_limited` — пауза по `Retry-After` |
| `/new`, `/new вопрос` | история с начала; с вопросом — сразу ответ на него |
| `/doc вопрос` | `/v1/documents/answer`: ответ, источники, цитаты — под маской ПД |
| `/status` | сразу, даже пока модель отвечает: сервис, модель, очередь (`/health` — вне лимита ключа), занят ли бот |
| `/help вопрос` | День 31: ассистент разработчика — `/v1/project/help`: ответ о проекте CRM, ветка git, источники, вызовы git — под маской ПД (точный профиль); в очереди чата, ход правками |
| `/start`, `/help` | справка — тоже сразу |

**Подтверждение updates.** Опрос обрабатывает updates последовательно по
`update_id`. Постановка в очередь не считается завершением. Следующий offset
сохраняется после окончательной доставки ответа, а подтверждение Telegram
происходит при следующем `getUpdates` с большим offset. При сетевом сбое,
429/5xx или неудачной окончательной отправке update остаётся для повтора.
Неподдерживаемые updates могут быть завершены без ответа согласно правилам
доступа и обработки типов сообщений.

Checkpoint `telegram-offset` содержит только следующий номер, а
`telegram-offset.pending` — версию перехода, прежний и следующий номера;
текстов сообщений, документов и ответов в них нет. Запись использует временный
файл, `fsync`, атомарную замену и синхронизацию каталога. Незавершённый переход
восстанавливается консервативно; повреждённое состояние вызывает отказ.
После аварии между доставкой ответа и сохранением checkpoint возможны
повторная обработка и повторный ответ. История разговора после рестарта теряется.
Эти гарантии действуют в пределах срока хранения updates Telegram.

**Фильтр ПД.** Telegram — внешнее облако, поэтому в ответах `/doc` фамилии из
локального `pd-names.txt`, отчества (вместе с именем), инициалы с фамилией (в
любом написании: «А.В.», «А.В», «А В.»; латинские двойники букв, которые
оставляет распознавание договоров, читаются как кириллица), e-mail и телефоны
заменяются на «[скрыто]», а под ответом — сколько и каких
видов скрыто. Затем весь текст проверяется ещё раз; если шаблоны что-то
находят — ответ не отправляется. **Фильтр не ловит:** адреса, ИНН, КПП, ОГРН,
расчётные счета, паспортные данные, фамилии не из списка. Тексты фрагментов
документов (контекст модели) в Telegram не уходят.

**Что остаётся на ноутбуке.** Журнал бота `memory/service/telegram.jsonl` —
только метаданные (кто: владелец / чужой — хэш ID; что; код; токены; время;
сколько скрыто ПД), без текстов. Процесс бота — в офлайн-режиме Дня 27 с одним
разрешённым внешним хостом `api.telegram.org`; токен в журнале сети заменён на
`/bot…/`, логгеры `httpx` не печатают адреса. Сервис по-прежнему не делает
внешних запросов.
