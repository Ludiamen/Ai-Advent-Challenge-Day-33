# Показ Дня 30 в браузере: сценарий для расширения Claude in Chrome

Этот файл — сценарий, по которому **браузерное расширение** само проходит
страницы и показывает **локальную LLM как приватный сервис**:
- сервис `day31-llm` (с Дня 31; в Дне 30 — `day30-llm`) — служба пользователя systemd на ноутбуке, HTTPS со своим
  сертификатом на адресе в домашней сети; Ollama слушает только 127.0.0.1;
- ключи API с правами, подсети, лимиты (запросов в минуту, очередь, вход в
  токенах, ответ);
- чат по OpenAI-совместимому API с потоком и ответ по документам с цитатой;
- отказы: нет права (403), длинный вход (413), лимит ключа (429);
- доступ по сети: клиенты из контейнера Docker и телефон в Wi-Fi;
- нагрузка вживую — 8 клиентов из Docker, очередь и повторы после 429 — и
  итог ступеней 1 → 2 → 4 → 8.

Под запись экрана сценарий разбит на восемь сцен с паузами.

От `MANUAL-CHECK.md` отличается адресатом. Там сценарий для человека: он видит
контекст, догадывается, чего ждать, и умеет открыть терминал. Здесь исполнитель —
расширение: у него нет терминала, нет памяти о прошлых днях и нет права на
догадку. Поэтому каждый шаг написан как «сделай это → должно появиться то», а
всё, что требует командной строки, человек делает заранее.

## Показ без расширения

```bash
bash demo_show.sh                 # ключи показа + видимый Chrome + запись + восемь сцен + ускоренная копия
bash demo_show.sh --no-record      # то же без записи
bash demo_show.sh --pause 4000     # длиннее паузы между сценами
```

Что он делает: проверяет, что служба работает, создаёт четыре ключа показа (в
поля они вводятся как пароль — в кадре точки), открывает **видимый** Chrome со
своим профилем, который доверяет только сертификату сервиса — по отпечатку его
ключа (`--ignore-certificate-errors-spki-list`), а не отключением проверок, —
включает запись **того самого окна**, проходит восемь сцен с подписями внизу
страницы, а в конце отзывает ключи показа и печатает путь к `demo/показ-*.mp4`.

Запись — без монтажа: генерации на CPU идут в кадре в реальном времени. Пока
модель думает, водитель пишет метки ожиданий, и `demo_speedup.py` собирает
**ускоренную копию** `demo/показ-*-ускорено.mp4`: ожидание — ×8 с надписью в
кадре, сцены — в обычной скорости.

Проверено живым прогоном: запись `1568×938` (только окно браузера), 11 минут
15 секунд, восемь сцен, «показ прошёл без расхождений»; ускоренная копия — 2
минуты 32 секунды. Записан с третьего дубля: в первом окно Chrome «Сохранить
пароль?» закрывало правую часть `/admin`, во втором один клиент нагрузки не
дождался ответа (см. RESULTS).
- **Сцена 1** — служба `day30-llm` active, `https://192.168.1.43:8443` в
  домашней сети со своим сертификатом; Ollama слушает только 127.0.0.1.
- **Сцена 2** — модель `loc-rag-docs`, ключи с правами (на диске — хэши),
  подсети, лимиты: 6 в минуту, очередь 1 + 4, вход ≤ 3400, ответ ≤ 600.
- **Сцена 3** — чат потоком: ответ за 22 с, вход 24, ответ 64 токенов, первый
  токен 1,4 с, `stop`.
- **Сцена 4** — по документам ключом «документы»: за 41 с «Не позднее 20 числа
  текущего месяца оказания услуг.», источник и цитата «✓ дословно»; тот же
  вопрос ключом «показ-чат» — 403 `permission_denied`.
- **Сцена 5** — вход 4304 токенов: 413 `context_length_exceeded` до вызова
  модели; семь запросов одним ключом — 200 × 6 и 429 `rate_limited`.
- **Сцена 6** — клиенты по журналу: 192.168.1.31 (телефон в Wi-Fi), 172.17.0.2
  (контейнер Docker), 192.168.1.43 (сам ноутбук).
- **Сцена 7** — 8 клиентов из Docker вживую (8 минут 54 секунды ожидания, в
  копии ×8): 8 из 8 ответов, ошибок 0, отказов 429 — 4, все прошли при повторе;
  задержка p50 223,5 с, p95 318,4 с.
- **Сцена 8** — ступени прогона `20261010-090429`: ошибок 0, задержка p50
  38 → 88 → 205 → 165 с, пик ОЗУ раннера 4818 МБ.

Отличие от расширения одно, и его стоит назвать в кадре: сцены ведёт скрипт, а не
модель в браузере. Всё остальное — настоящее: служба, модель на CPU, клиенты по
сети.

В конце показ печатает «показ прошёл без расхождений» или перечисляет, что
разошлось с ожиданиями сцен.

## Если что-то пошло не так

- **«Служба day30-llm не работает»** — `python cli.py --сервис старт`; журнал службы —
  `journalctl --user -u day30-llm`.
- **Предупреждение о сертификате** — адрес ноутбука сменился: `python cli.py
  --сервис-сертификат`, затем `python cli.py --сервис перезапуск`.
- **«HTTP 403 · forbidden_network»** — ноутбук в другой сети, чем в `service.json`
  («подсети»).
- **Ответ идёт больше 10 минут** — машина под чужой нагрузкой: `uptime`.

## Дополнение: показ Telegram-бота

Бот — чат владельца с той же моделью через сервис ([SERVICE.md](SERVICE.md),
«Telegram-бот»). Показ идёт в **Telegram Web владельца** — отдельном профиле

кадр в одной из записей (её нет). Скрипт пишет **только в чат с ботом** и перед
каждой отправкой сверяет заголовок чата.
