# AI-ревью PR (День 32)

На каждый PR в этом репозитории GitHub Actions запускает ассистента-ревьюера. Он
получает diff и изменённые файлы, находит опору в документации и коде проекта (RAG) и
пишет в PR один комментарий из трёх разделов: **потенциальные баги**, **архитектурные
проблемы**, **рекомендации**. Если в багах или архитектуре есть подтверждённая
критичная находка, проверка PR становится красной. Слияние всегда решает человек.

Устройство — [ARCHITECTURE.md](ARCHITECTURE.md), раздел «AI-ревью PR (День 32)».
Требования и решения — [specs/032-code-review/](specs/032-code-review/).

## Как это работает

```
PR opened / synchronize / reopened / ready_for_review
  └─ .github/workflows/ai-review.yml → python review.py --github
       1. вход     git-сервер MCP (только чтение): git_changes → git_diff → git_show
       2. индекс   документы и код БАЗЫ PR (не головы): PR не может переписать правила,
                   по которым его проверяют; поиск — BM25, без модели эмбеддингов
       3. опора    запросы из diff + места вызова изменённых функций (git_grep)
       4. ревьюеры баги │ архитектура │ рекомендации — параллельно, ds-flash, JSON
       5. сборщик  код проверяет каждую находку: файл из PR, строка в изменённом
                   участке, цитата diff найдена, источники выданы; дубли сливаются
       6. выход    комментарий (обновляется, не плодится), сводка задания,
                   артефакт метрик, Telegram владельцу при красном или сбое
```

Код выхода шага: 0 — 🟢, 1 — 🔴, 2 — ревью не выполнено (сбой модели, нет ключа).

## Включить в своём репозитории

1. Скопировать `.github/workflows/ai-review.yml`, `review.py`, `requirements-review.txt`,
   `git_server.py`, `mcp-servers.json` (сервер `git`), `projects.json` (проект
   `advent` — поправить «включить / исключить» и «описание» под свой проект) и пакет
   `agent/` (нужны `agent/review`, `agent/rag`, `agent/devassist`, `agent/mcp`,
   `agent/llm.py`, `agent/catalog.py`, `agent/service/pd.py`).
2. **Settings → Secrets and variables → Actions → New repository secret:**
   - `DEEPSEEK_API_KEY` — ключ модели;
   - `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — по желанию, для уведомлений.
3. Права workflow заданы в самом файле: `contents: read`, `pull-requests: write`.
4. По желанию — **Settings → Branches → защита `main`**: требовать проверку «AI-ревью»
   перед слиянием. Без этого красная проверка только предупреждает.

## Границы и безопасность

- Триггер `pull_request`, а не `pull_request_target`: PR из форка не получает секретов,
  и его ревью пропускается с пояснением (владелец может запустить `python review.py
  --pr N` сам).
- У ревьюеров нет инструментов, которые меняют репозиторий или GitHub: только
  `git_show` по двум коммитам PR. Слияния, push, правок нет по построению.
- diff, заголовок и описание PR — данные: они в метках «данные PR», подделка меток
  обезврежена, инструкции внутри не выполняются (это повод для находки).
- Текст модели перед публикацией: маска ПД, экранирование HTML, `@` не становится
  упоминанием, ссылки и картинки модели не становятся ссылками.
- Ключи — только в Secrets, токен GitHub — только у шага ревью; `actions/checkout`
  без сохранения учётных данных.
- Код ревьюера берётся из PR (так устроен `pull_request`): PR от участника с правом
  записи может изменить и ревьюера. Для чужих — форк, где секретов нет.

## Метрики и качество

Каждый прогон пишет строку без текстов: время по этапам, токены и стоимость по
ревьюерам, файлы, фрагменты опоры, находки по разделам и серьёзностям, сколько
подтверждено и понижено, вердикт, сбои. Строка — в скрытой части комментария, в
артефакте `review-metrics` и локально в `memory/review/metrics.jsonl`. Если прогон вдвое
дороже или дольше медианы последних 20 — тревога в комментарии и в Telegram.

Оценка человеком — реакции 👍 / 👎 на комментарий ревью. Сводка:
`python cli.py --ревью-метрики` (локальные прогоны) и `--ревью-метрики --гитхаб`
(прогоны и оценки из комментариев репозитория).

Качество проверяется контрольным набором `review-cases.json` (посеянные ошибки и чистые
изменения): `python check_review.py`.

## Локально

```bash
python review.py --база main --голова HEAD     # ревью своей ветки, без публикации
python review.py --pr 3                        # PR №3 с GitHub: ревью и комментарий (GITHUB_PAT)
python cli.py --ревью main...HEAD              # то же из консоли агента
```

В чате агента (консоль и страница `/chat`): `/review` или `/review main...HEAD`.
