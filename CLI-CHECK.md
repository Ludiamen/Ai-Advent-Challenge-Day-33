Мок-трекер поднимает сам скрипт прогона — на свободном порту и со своими
данными в `cli-check-memory/tracker-data.json`. Работника он тоже запускает сам,
там, где это нужно по шагу. Руками запускать ничего не нужно.

```bash
cd ~/Документы/AI-Advent-Challenge/Day-30
.venv/bin/python check_cli.py                # весь чек-лист + отчёт в CLI-CHECK-RESULTS.md
.venv/bin/python check_cli.py --без-модели   # без живых вызовов модели
.venv/bin/python check_cli.py --в отчёт.md
```

Ниже вместо `.venv/bin/python` написано просто `python`: так короче, а с
активированным окружением (`source .venv/bin/activate`) это одно и то же.
Команды подразумевают файл серверов прогона
(`cli-check-memory/mcp-configs/orchestra.json` для оркестровки,
`…/pipeline.json` для конвейеров, `…/scheduler.json` для планировщика,
`…/tracker.json` для трекера); вручную то же самое делается с
`mcp-servers.json`, если в соседнем терминале поднят `python tracker_api.py`.

Память у всего прогона одна (`cli-check-memory/`), поэтому номера заданий,
заявок, прогонов и флоу сквозные: заявку №1 заводит длинный флоу из части 3,
№2 — конвейер из части 6, №3 — планировщик из части 9, №4 — трекер из части 15.

Индекс для части 0 — копия рабочего `index/` в `cli-check-memory/index/`
(ключ `--индекс-в`). Рабочий индекс собирается заранее одной командой
`python cli.py --индексировать`: первая сборка на CPU идёт около часа (OCR
сканов и векторы bge-m3), а в копии все векторы уже в кэше, и пересборка в
чек-листе идёт секунды. Ollama с моделью `bge-m3` должна быть запущена.
